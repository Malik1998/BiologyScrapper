# faces-dataset

Фото известных людей 40-50 лет + они же в 20-30 + их родители в 40-50.
Возраст на каждом фото **вычислен**, а не оценен на глаз.

## Структура

```
dataset/
  <slug>/
    subject_now_age42.jpg          полный кадр
    subject_now_age42_face.jpg     кроп лица
    subject_young_age30.jpg
    father_40s_age46.jpg
    mother_40s_age50.jpg
    meta.json                      возраст, источник, лицензия, доказательства
  _sheets/sheet_01.jpg             контактный лист для просмотра глазами
  index.json                       сводка по всем
  report.txt                       таблица покрытия
```

Слоты: `subject_now` (40-50), `subject_young` (20-30), `father_40s`, `mother_40s`.
Минимальный набор — субъект в обоих возрастах + хотя бы один родитель.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install opencv-python-headless pillow numpy
.venv/bin/python tools/harvest_all.py -j 4 --top 60     # сбор (seed_people.json)
.venv/bin/python tools/harvest_all.py "Имя" "Имя2"      # конкретные люди
.venv/bin/python tools/harvest_all.py --retry-missing   # дозаполнить пустые слоты
.venv/bin/python tools/sheet.py 8                       # контактные листы
.venv/bin/python tools/index.py                         # сводка
```

Прогресс пишется в `work/harvest_state.json`, повторный запуск продолжает с места
остановки. `--redo` игнорирует состояние. Скачанные файлы кэшируются в `work/cache/`.

Уже заполненные слоты при повторной сборке человека не трогаются: запросы
тратятся только на пустые, и готовый слот не может стать хуже.

В `tools/seed_people.json` у записи можно указать `qid` (точный элемент Wikidata,
если имя неоднозначно) и `father_qid` / `mother_qid` (родитель, которого в
Wikidata не связали с ребёнком).

## Перенос на другую машину

```bash
./pack.sh              # результаты + код + модели + скилл, ~80 МБ
./pack.sh --cache      # то же плюс кэш скачанных фото, ~700 МБ
# на новой машине:
tar xzf faces-dataset-transfer.tgz && ./setup.sh
```

`setup.sh` пересоздаёт venv, докачивает модели и ставит скилл, после чего
сбор **продолжается**, а не начинается заново.

Три вещи, которые ломают наивное копирование папки:

- **`.venv` переносить нельзя** — в нём зашиты абсолютные пути к питону этой
  машины. `pack.sh` его исключает, `setup.sh` создаёт заново.
- **Скилл лежит вне проекта**, в `~/.claude/skills/face-age-dataset/`. При
  копировании одной папки проекта он потеряется; `pack.sh` кладёт его в архив.
- **Прогресс определяется по самому датасету**, а не только по
  `work/harvest_state.json`: раннер восстанавливает состояние из
  `dataset/*/meta.json`. Иначе люди, собранные до появления файла состояния,
  пересобирались бы заново.

Кэш (`work/cache`, ~620 МБ) — просто скачанные превью. Без него уже собранные
люди никуда не денутся, но пересборка кого-то из них снова полезет в сеть.

## Откуда берутся данные

- **Wikidata** — дата рождения (P569), отец (P22), мать (P25), эталонный портрет
  (P18), категория Commons (P373). Поэтому добавить человека стоит одного имени:
  родители находятся сами.
- **Wikimedia Commons** — сами фото с датой съёмки в метаданных.

## Второй источник: Flickr

Если на Commons для слота меньше 30 кандидатов, добавляется поиск по Flickr:
фото с точной датой съёмки (`date_taken`, только `granularity = 0`) и открытой
лицензией (CC BY, CC BY-SA, CC0, Public Domain, US Gov; NC/ND не берутся).
Дальше те же проверки лица и личности. В `meta.json` у слота `source: flickr`.

Нужен бесплатный ключ API: https://www.flickr.com/services/apps/create/
(«Apply for a non-commercial key»). Положить его в `work/flickr_key` или в
переменную `FLICKR_API_KEY`. Без ключа источник просто пропускается.

## Третий источник: поиск картинок в интернете

Если и после Commons кандидатов меньше 30, ищется `"Имя" <год>` через
метапоиск `ddgs` (DuckDuckGo/Bing) по каждому году окна. Результат берётся,
только если год стоит **в подписи** к картинке и других лет там нет: год из
одного лишь URL — это обычно дата статьи (свадебное фото Питера Филлипса 2008
года пришло как «2018»). Стоковые сайты с водяными знаками отбрасываются.

У таких фото нет открытой лицензии — только для внутреннего исследования, не
для публикации. Они всегда помечены `source: web`, `needs_visual_check: true`
и проходят ручную проверку:

```bash
.venv/bin/python tools/review_web.py build   # листы в dataset/_sheets/web_review/
# вердикты -> work/web_review.json: {"<slug>/<slot>": {"ok": false, "note": "..."}}
.venv/bin/python tools/review_web.py apply   # убрать отклонённые, слот снова пустой
```

Отклонённая картинка запоминается и при повторном сборе не выбирается.
`--no-web` отключает этот источник.

## Как проверяется возраст

`age_at_photo = дата съёмки − дата рождения`. Дата берётся в таком порядке:

1. год из категории `X by year` (проставлен куратором по событию);
2. EXIF `DateTimeOriginal`, если не противоречит категориям;
3. при противоречии выигрывает категория, ставится `date_conflict: true`.

Пункт 3 — не формальность. Семейное фото Клинтонов 1993 года имеет в EXIF
`2021-06-17` (дата оцифровки архива), и без этой проверки 13-летняя Челси
получала возраст 41.

Если дату подтвердить нечем — фото выбрасывается, а не датируется наугад.

## Как проверяется, что это нужный человек

Почти все фото публичных людей — групповые, и самое крупное лицо в кадре
регулярно принадлежит не тому человеку. Поэтому лицо выбирается матчингом
**SFace** против эталонного портрета из Wikidata, а не по размеру.
`identity_cosine` в `meta.json` — это доказательство.

Матчинг через 20 лет возраста слабее, поэтому для `subject_young` порог ниже.
Низкий `identity_cosine` (< 0.45) не значит «неправильный человек» — значит
«проверь глазами». Молодой Дональд Трамп даёт 0.37 против современного эталона
и при этом абсолютно верен.

## Что отбраковывается автоматически

- `eyes_occluded` — тёмные очки: все геометрические метрики у такого лица
  отличные, но глаз не видно;
- `face_too_small` — лицо меньше порога межзрачкового расстояния;
- `identity_below_threshold` — лицо не похоже на эталон;
- `no_reference_and_multiple_faces` — эталон не построился, а в кадре несколько
  лиц. Выбор «самое крупное» там означал бы угадывание: однажды он выдал в слот
  Лив Тайлер мужчину.

## Что смотреть глазами

Контактный лист: строка — человек, колонка — слот, на каждом тайле возраст,
дата, `id` и межзрачковое расстояние. Красные флаги:

- `id` < 0.45 — подтвердить личность;
- `date_precision = year` вместе с `date_conflict` — подтвердить возраст;
- `eye` < 60 — лицо мелкое, вероятно стоит взять `runners_up` из `meta.json`;
- возраст у самого края диапазона.

## Ограничения

- Пригодность определяют **родители**, а не слава субъекта. У обычной знаменитости
  родителей никто не снимал в 40-50 — четвёртого фото не существует. Рабочий
  срез: дети политиков, монархов, актёров, музыкантов.
- Родитель мог не дожить до 40 (Диана погибла в 36) — слот честно падает.
- Commons режет частоту запросов; параллелизм сделан потоками в одном процессе,
  потому что троттл общий. Отдельные процессы получают свой бюджет каждый и ловят 429.
  Если 429 не проходит даже после долгого ожидания, человек помечается `error` и
  пересобирается при следующем запуске, а не записывается как «фото нет».
- Лицо, мелкое в рабочей копии 1280 px, перепроверяется на оригинале (до 3840 px)
  с абсолютным порогом 40 px между зрачками: так спасаются кадры с мероприятий.
- Превью запрашиваются только стандартных ширин Wikimedia (960, 1280, 1920,
  3840 …): любую другую ширину сервер отклоняет с 429.
- Имя сопоставляется с Wikidata по точному совпадению с названием элемента;
  совпадение только с псевдонимом слабее (у Пола Маккартни есть псевдоним
  «James McCartney» — это имя его сына).
- Wikidata Query Service часто недоступен; автоподбор имён через SPARQL
  необязателен, есть `tools/seed_people.json`.
- Фото под разными лицензиями (CC BY, public domain и др.), `license` и `author`
  сохраняются в `meta.json` — при публикации указывать атрибуцию.
